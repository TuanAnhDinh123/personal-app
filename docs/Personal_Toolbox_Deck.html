The demo you are about to see

One hiring run, end to end.

Seven steps. Today six of them involve retyping. In the app, a candidate is entered once at step 3 and that same record carries all the way to step 7.

  1. Receive — a folder of CV files
  2. Name — file names normalised into batch codes
  3. Read & score — AI reads each CV against the position's job description
  4. Shortlist — search and filter one candidate list
  5. Invite — Outlook invitations with the CV attached
  6. Evaluate — feedback per interviewer, per round
  7. Report — the Excel file you already know, in one click
Step 1–2 · CV intake

Every CV gets the same name, every time.

The batch code follows the candidate from the file name to the final report.

  • Point the app at the folder of CVs you received.
  • Normalize file names: pick a prefix and a starting number, list the words to strip out of candidate names.
  • Preview before / after in a table — and correct any name by hand — then rename the whole batch at once.
  • Result: PREFIX0123_Candidate Name.pdf, one rule for everyone.
Step 3 · AI CV Scan

The AI reads every CV against that position's job description.

  • Choose the position — the app already knows which job description belongs to it. Nobody hunts for a JD file.
  • Add your own instructions if you want: "must have electronics manufacturing background".
  • It runs in the background with a progress bar — the app stays usable.
  • Same email or phone as an existing candidate? It stops and asks. It never quietly merges two people.

Reading and summarising forty CVs is an evening of work. Here the result isn't a note in your head — it is data you can still search next year.

Step 4 · Candidate list

One list, and it answers questions.

"Who did we interview for this role last year, and why didn't we hire them?" becomes a search instead of an excavation.

  • Free-text search across the whole candidate record.
  • Filters that match how we talk: Position · Department · Status · Batch.
  • Click the CV file name to open the PDF. Moved or renamed? Point at it once — the app remembers the new location.
  • Tick several candidates and act on all of them together.
  • Right-click for Quick edit (interview feedback) and Update source — the job board or referral the CV came from, set for the whole selection at once.
Step 5 · Invitations

Interview invitations, prepared for you — sent by you.

  • Tick the candidates, choose the round: 1st · 2nd · 3rd.
  • The app uses the email template attached to that position for that round, so the wording is the same whoever sends it.
  • Set a time per candidate — the next one is pre-set to follow on, and Skip passes over anyone you'd rather schedule later.
  • It opens one Outlook meeting window per candidate: recipient, CC, time, template body — and the CV attached.
  • You add the room and press Send. Outlook handles invitation, calendar and booking.
  • Right after, it offers to move exactly those candidates to the next status.

Notice what it deliberately does not do: it never sends anything by itself. Every mail stops in front of you first.

ALSO

Application Thank You

Opens a normal mail instead — no time slots, no meeting, and the candidate's status is left exactly where it was.

Step 6 · Interview feedback

Feedback keeps the name of the person who wrote it.

The full candidate form has thirty fields. The thing you do after every interview needs five — so it has its own short form.

  • Status · result · phone screen date and note.
  • For each of the three rounds: date, overall result, and as many interviewers as attended — each with their own conclusion and comments.
  • Interviewer names come from the employee directory, so title and department are looked up, never retyped.
  • Dates open a calendar, show dd/MM/yyyy, and may be left empty — a round that hasn't happened yet doesn't get a meaningless date.
  • In the Excel report, each comment still carries its author. Nothing is merged into one anonymous paragraph.
Step 7 · Reporting

The Excel file stays. It is generated, not maintained.

  • The familiar Candidates sheet — 25 columns, A to Y: batch, ID, name, position, source, contact, score, AI evaluation, status, result, phone screen, and four columns for each of the three rounds.
  • Dropdown lists on the columns that should be chosen rather than typed.
  • Status and result colour-coded; duplicate email addresses flagged in red.
  • File already exists? It asks: Append · Overwrite · Cancel. It never silently rewrites a file you already sent to someone.

Employees

The master headcount file, with the fragile parts removed.

  • ~90 fields, matching our Master HC file almost column for column.
  • Bulk import matches by column heading, not column position — reorder or add columns and the import still lands correctly.
  • Emergency contact arrives as one messy cell (name and number mixed, in every possible format) — the app splits it into name and phone on import.
  • Working / resigned is derived from the termination date, so the two can never disagree. Resigned colleagues hidden by default, one tick to show them.
  • 90 columns would be unreadable: a sensible default set is shown, the rest switch on in Columns, grouped as Identity · Contact · Education. Your choice is remembered.

Training

A signed attendance sheet updates the training records.

Nobody should be paid to tick a hundred boxes that a scan already answers.

  • Enroll employees onto a course straight from the employee list.
  • Course Manager shows every enrolment and its learning status.
  • We print the roster, everyone signs by hand, the stack is scanned into one PDF.
  • The app splits that PDF page by page, finds which rows carry a handwritten signature, matches them by employee code, and marks those people Completed.

Six rules the app follows everywhere
01

AI never writes without a human

Every AI result — CV score, application form, signature sheet — lands in a screen you approve first.

02

Nothing is overwritten silently

Duplicate candidates, duplicate employees, existing Excel files: the app asks, and Cancel is always one of the answers.

03

History is added, never replaced

Each AI evaluation is kept with its date, the model used, and which version of the CV it read. You can see how an assessment changed.

04

Machine-written columns are locked

Batch, ID, score, AI evaluation. Editing those by hand would corrupt the evaluation history, so the app doesn't allow it.

05

Shared lists instead of free typing

Departments, levels, positions, statuses and email templates live in one directory used by every screen.

06

Small details, on purpose

Dates always dd/MM/yyyy and allowed to be empty · the scroll wheel can't change a date by accident · phone numbers keep their leading zero in Excel · long jobs run in the background instead of freezing the window.

Before you ask

Where AI is used — and where it is not.

Used forNever used for
Reading a CV and scoring fit against the JD Deciding who to hire or reject
Reading a completed application form Writing anything into the records unreviewed
Reading handwritten signatures on a scanned roster Sending any email on its own
Turning scanned PDFs back into text Anything at all while you are offline
  • What leaves the machine: only the specific file being read, for that one request. Nothing is uploaded in the background.
  • The AI key is set once in Settings and shared by every AI feature.
  • If AI is unavailable, every screen still works — you type instead of it reading.
